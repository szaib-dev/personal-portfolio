# How It Works

## Content Flow
1. Static content lives in `src/content/` (instant load, zero latency)
2. Convex stores the same content as overrides (editable from admin)
3. Frontend hooks check Convex first, fall back to static if empty
4. Result: instant page load + live editability

## Adding a New Project
1. Create `src/content/projects/your-project.ts` (copy structure from existing)
2. Import and add to `src/content/projects/index.ts`
3. Admin dashboard auto-generates image upload sections for it
4. Upload images via `/admin`
5. Project page is live at `/projects/your-project-slug`

## Admin Panel
- `/admin` — Image manager (login required)
- `/admin/content` — Content editor (profiles, projects, references, values, about)
- Auth: email + password stored in Convex environment variables

## Deployment
- Frontend: Vercel
- Backend: Convex Cloud
- Images: Convex File Storage

## Environment Variables

### Vercel (production)
- `NEXT_PUBLIC_CONVEX_URL` — Convex deployment URL

### Convex Dashboard (environment variables)
- `ADMIN_EMAIL` — Admin login email
- `ADMIN_PASSWORD` — Admin login password

## Commands
- `npm run dev` — Start Next.js dev server
- `npx convex dev` — Start Convex dev (watches for changes)
- `npx convex deploy --typecheck=disable` — Deploy Convex to production
- `npx convex run seed:seedAll` — Seed database with initial content
- `npx convex run --prod seed:seedAll` — Seed production database

## Case Study Block Types
Each project page is built from these block types:
- `overview` — Project overview with 4 info cards
- `section` — Two-column text section (label + title + body)
- `persona` — User persona card with goals and frustrations
- `gallery` — Image grid (columns: 2, 3, 4, or 5 for mobile mockups)
- `palette` — Color swatches
- `typography` — Font samples
- `quote` — Blockquote
- `image` — Single full-width image
